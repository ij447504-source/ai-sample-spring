# Code Convention

## 1. Package Structure

- 코드는 기능별로 패키지를 그룹화하여 관리합니다.
- 예: `com.example.demo.user`, `com.example.demo.board`

## 2. Naming Convention

- 클래스명은 `PascalCase`를 사용합니다.
- 메소드와 변수명은 `camelCase`를 사용합니다.

### 2.1. Domain Classes

도메인 클래스는 다음의 접미사(suffix)를 사용합니다.

- **`{Domain}`**: Entity (예: `User.java`, `Board.java`)
- **`{Domain}Controller`**: Controller (예: `UserController.java`)
- **`{Domain}Service`**: Service (예: `UserService.java`)
- **`{Domain}Repository`**: Repository (예: `UserRepository.java`)
- **`{Domain}Request`**: Request DTOs
- **`{Domain}Response`**: Response DTOs

## 3. Class Structure

### 3.1. General

- Lombok 어노테이션을 적극적으로 사용하여 Boilerplate 코드를 줄입니다.
  - `@Data`, `@NoArgsConstructor`, `@RequiredArgsConstructor`, `@Builder`
- 의존성 주입은 생성자 주입을 사용하며, `final` 키워드와 `@RequiredArgsConstructor`를 함께 사용합니다.

### 3.2. Controller

- View를 반환하는 경우 `String`을 반환합니다.
- 데이터를 반환하는 경우 `ResponseEntity`에 `Resp` DTO를 담아 반환합니다.

### 3.3. Service

- 비즈니스 로직을 포함합니다.
- 클래스 레벨에 `@Transactional(readOnly = true)`을 선언하여 트랜잭션을 관리합니다.
- **DTO는 Service에서 만들어서 Controller로 전달합니다. Entity를 Controller에 절대 전달하지 않습니다.**

### 3.4. Entity (JPA)

- 데이터베이스 테이블과 매핑되는 클래스입니다.
- 테이블명은 `snake_case`를 사용하여 명시적으로 지정합니다. (예: `@Table(name = "user_tb")`)
- **규칙: 모든 연관관계는 Lazy Loading (`FetchType.LAZY`)을 원칙으로 합니다.** (OSIV는 false로 설정)

### 3.5. DTO (Data Transfer Object)

- Request/Response 데이터를 전달하는 객체입니다.
- 각 도메인의 `Request`, `Response` 클래스 내부에 static inner class로 정의합니다.
- 예: `UserRequest.Login`, `BoardResponse.Detail`
- `@Data` 어노테이션을 사용하여 getter, setter, toString 등을 자동으로 생성합니다.
